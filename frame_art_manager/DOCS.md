# Frame Art Manager Documentation

## Overview

Frame Art Manager helps you organize and manage artwork for your Samsung Frame displays. Upload images, organize them with tags, and sync changes to your shared library. TV discovery, assignment, and display automation now live in the Home Assistant integration rather than the add-on UI.

## Accessing the Add-on

### After Installation

1. Go to **Settings** → **Add-ons** → **Frame Art Manager**
2. Ensure the add-on is started (check for green indicator)
3. Click **Open Web UI** to access the interface

### Alternative Access Methods

- **Direct URL**: `http://[your-home-assistant-ip]:8099`
- **Sidebar Panel**: Look for "Frame Art Manager" in the Home Assistant sidebar
- **Dashboard**: Add a Webpage card pointing to the add-on URL

### Adding to Dashboard

To add Frame Art Manager to any dashboard:

1. Edit your dashboard
2. Add a **Webpage Card**
3. Set URL to: `http://homeassistant.local:8099`
4. Adjust aspect ratio as desired (100% recommended)

## Interface Overview

The web interface has 4 main areas:
- **Gallery**: Browse and manage your images
- **Upload**: Add new images to your library
- **Tags**: Manage your tag library
- **Advanced**: System information and settings (including metadata viewer and sync details)

## Configuration

### Home Label (Optional)

Set the **Home** field to a nickname like `Madrone` so future automations can tell which location this add-on instance belongs to. The value is optional today but is passed to the backend for upcoming features.

### Connecting Your Art Library to GitHub

The library (images, thumbnails and `metadata.json`) can live in a private GitHub
repository, which backs it up and keeps every copy in sync. Images are stored with Git LFS.
The add-on sets this up from its web UI; no terminal or SSH commands are needed. You can do
it on a new install, or later, after using the add-on without sync for a while.

On a new install (the library folder, `frame_art_path`, is empty) the web UI opens on
**Connect your art library**. Any time the library is not connected yet, the same screen
opens from **Advanced → Settings → Library Sync → Set up GitHub sync**.

The screen starts with a **GitHub connection** panel, so a problem shows up before any
repository is involved:

- **SSH key**: generated by the add-on, or taken from `ssh_private_key`.
- **GitHub**: whether the add-on reaches GitHub (`ssh.github.com`, port 443). If not, the
  network, DNS or a firewall in front of Home Assistant is the problem, not the repository.
- **Key recognized**: whether GitHub knows the key yet. While it does not, the panel checks
  again every few seconds, so it turns green on its own once the deploy key is added.

GitHub tells which repository a deploy key belongs to, so once the key is added the screen
fills in the repository name and tests it by itself. If you typed a different repository than
the one the key is on, the panel says so.

1. **Create a private repository** on GitHub (the link opens
   `https://github.com/new?name=frame_art&visibility=private`). Leave it empty: no README,
   no license. To download an existing Frame Art library instead, use its repository.
2. **Enter the repository** as `owner/name`, for example `your-user/frame_art`. You can skip
   this: it is filled in once the key is added (step 3), from the repository's own
   **Settings → Deploy keys** page.
3. **Add the add-on's key as a deploy key.** Copy the public key shown on the screen, open
   the repository's deploy keys page (the link goes to
   `https://github.com/<owner>/<repo>/settings/keys/new`), paste it, give it a title and
   check **Allow write access**. Without write access the add-on can download the library
   but cannot save your changes.
4. **Test connection.** The test tells you whether GitHub accepts the key, whether the key
   can write, and what connecting will do.
5. **Connect library.**
   - Empty repository: the library in the folder becomes the repository's first commit and
     is pushed to the `main` branch: your images, thumbnails, originals and
     `metadata.json`, or an empty library on a new install. The add-on adds a
     `.gitattributes` (Git LFS for images) and a `.gitignore` (desktop clutter such as
     `.DS_Store`). A large library takes a while to upload, and counts against your GitHub
     account's Git LFS storage.
   - Repository that already holds a library: the add-on downloads it into the folder (the
     `main` branch, then the images through Git LFS). This needs a library folder without
     images of its own: merging two libraries is not supported, and the test says so.

Sync works as soon as setup finishes; the page reloads into the gallery. **Set up later**
closes the screen.

Setup never moves, replaces or deletes your files. A folder that is already a git
repository never sees the screen and is left exactly as it is. If connecting fails, setup
removes only what it added (`.git`, `.gitattributes`, `.gitignore`), so you can try again.

#### Checking on Sync

**Advanced → Settings → Library Sync** shows the same **GitHub connection** panel for a
connected library, plus how its sync stands:

- **Waiting to upload**: commits made here that are not on GitHub yet. This stays above zero
  when pushes fail, so it is the place to look when another copy of the library is missing
  recent changes.
- **Not saved yet**: changed files not committed by a sync yet.
- **Last upload**: the last push from this add-on. **Last check for changes**: the last time
  it fetched from GitHub.
- **Last sync failed**: shown only while no sync has worked since, with Git's error.

The panel is checked when the tab opens; **Check again** re-runs it.

#### Changing or Disconnecting the Repository

**Advanced → Settings → Library Sync** shows the repository the library syncs with.
**Disconnect…** stops syncing with it; nothing is changed or deleted on GitHub. Choose what
happens to the library on this add-on:

- **Keep the images here**: the library keeps working, without sync. To move it to another
  repository, create a new, empty one and run **Set up GitHub sync**: the library is
  uploaded there as a fresh start, and its history stays in the old repository.
- **Remove the images from this add-on**: empties the library folder so you can download a
  different repository's library (or the same one again) with **Set up GitHub sync**. The
  add-on first fetches from the repository and refuses if anything here is not on GitHub
  yet (sync first). Until a library is downloaded again, this add-on has no images.

GitHub allows a deploy key on one repository only. Before adding the add-on's key to a
different repository, delete it from the old one (**Settings → Deploy keys** on GitHub);
otherwise GitHub answers "Key is already in use".

#### The generated key

When `ssh_private_key` is empty, the add-on generates an ed25519 key on first start and keeps
it in its private data folder (`/data/ssh/id_ed25519`), so it survives restarts and updates.
Only the public half is ever shown. Removing the deploy key on GitHub revokes the add-on's
access. Uninstalling the add-on deletes the key; a reinstall generates a new one, which then
needs adding as a deploy key again.

### Using Your Own SSH Key (Existing Setups)

The `ssh_private_key` option still works and takes precedence over the generated key:

1. Go to **Settings** → **Add-ons** → **Frame Art Manager** → **Configuration**
2. Paste your SSH private key in the `ssh_private_key` field
3. Set `git_remote_host_alias` to match your Git remote host (default: `github-owner`)
4. Save and restart the add-on

**To get your SSH private key:**
- From Terminal & SSH add-on: `cat ~/.ssh/id_ed25519`
- Copy the entire output including `-----BEGIN` and `-----END` lines

**Note**: The private key is stored securely in the add-on's configuration and is never exposed in logs.

Either key is used over SSH on port 443 (`ssh.github.com`), which works on networks that
block port 22.

## Storage Location

- Images are stored in: `/config/www/frame_art/library/`
- Thumbnails are stored in: `/config/www/frame_art/thumbs/`
- Metadata is stored in: `/config/www/frame_art/metadata.json`
